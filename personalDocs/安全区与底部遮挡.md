# 安全区与底部遮挡

原则：不按机型 / UA 判断；只用安全区 token + 布局类型 + 真实可视高度。

## 底部被挡情况分类

｜现象｜本质｜解决办法｜
｜---｜---｜---｜
｜底栏整块不见，滑也滑不出｜壳层比真实可视区高，或画布撑高后被 overflow: hidden 裁掉｜修视口高度 / 画布 fallback｜
｜底栏可见，但被手势条遮挡｜内容区底部 padding 不够｜加 safe-bottom / Tab 高度避让｜

## 基础约定

**Viewport**（nuxt.config）
`viewport-fit=cover`，否则 `env(safe-area-inset-bottom)` 常为 0。

**全局 token**（global.css）

- `--safe-bottom`: `env(safe-area-inset-bottom, 0px)`
- `--tabbar-height`: 56px

**外层锁高 + 内层滚动**

- html / body / #\_\_nuxt：锁死可视高度，body { overflow: hidden }
- 业务页自己 overflow-y: auto，不要指望 document 滚出被裁区域

## 壳层高度（防虚高裁底）

问题：安卓地址栏 / 底栏导致 100% 虚高。

做法：

1. CSS：100% → 100dvh → var(--app-viewport-height, 100dvh)
2. 首屏脚本 app-viewport-height-boot.ts：用 visualViewport.height（回退 innerHeight）写入 --app-viewport-height，并跟 resize / 横竖屏 / 软键盘更新
   首屏脚本 app-viewport-height-boot.ts：用 `visualViewport.height`（回退 `innerHeight`）写入 `--app-viewport-height`，并跟 resize / 横竖屏 / 软键盘更新

业务页继续 height: 100% 吃壳，不要再写 100vh / 100dvh。

## 375 画布缩放（防旧浏览器 Tab 丢失）

问题：Samsung Internet 15 等不支持 `cqi/cqh` 时，`height / transform` 整段失效 → 画布随内容撑高 → Tab 落在裁剪线外。

做法（tabbed / default）：

- 默认：`width/height: 100%，transform: none`（旧浏览器）
- 仅 `@supports (width: 1cqi)`：保留原来的 375 + scale（现代机不变）

不按 UA 分流

## 内容避让（防压在 Tab / 手势条下）

- 有底部 Tab
  - `definePageMeta({ layout: 'tabbed' })`
  - layout 已给 main：`padding-bottom: calc(var(--tabbar-height) + var(--safe-bottom))`
  - BottomTabBar 自身：`height / padding-bottom` 也吃 `--safe-bottom`
  - 业务页不要再叠一层 Tab 高度

- 无 Tab、底部固定按钮 / 抽屉
  - `bottom` 或 `padding-bottom: calc(... + var(--safe-bottom))`

- JS 需要像素 / 判断是否 tabbed
  - 用 `useBottomChrome（hasTabBar、safeBottomPx、bottomOffsetCss）`
  - 禁止解析 userAgent

# 本次bug剖析

375 设计画布依赖 `cqi/cqh` + `transform: scale`，旧浏览器（如 Samsung Internet 15）整段失效；再叠加壳层 `overflow: hidden`，就分别表现为「底被裁」和「右露白」。

## 壳层工作方式：

```
html/body（锁死可视高度，overflow:hidden）
  └─ .app-shell（width:100%，overflow:hidden）
       └─ .app-shell__canvas（设计 375，再 scale 铺满）
            ├─ main（页面滚动）
            └─ BottomTabBar（absolute; bottom:0）
```

- 外层不滚，只由页面内部滚。
- Tab 贴在 canvas 底，不在滚动容器里 → 一旦画到裁剪线外，怎么滑都出不来。
- `transform: scale` 只改视觉，不改布局盒；公式必须成套生效，否则宽/高会对不齐壳层。

## Tab 底栏丢失

### 原因

1. 高度公式失效
   height: calc(100cqh \* 375px / 100cqi) 在无 cqi 时整条丢弃 → 画布 height: auto，随内容撑高（Profile 还有 min-height: 756px）。
2. 壳层裁剪
   .app-shell / body 锁在视口高度且 overflow: hidden → canvas 底部（含 Tab）落在可视区外。
3. （叠加）视口虚高
   旧安卓 100% / 假 innerHeight 偏大时，壳比真实可见区还高，底更容易被「看不见地」裁掉。

### 方法

| 层         | 做法                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------ |
| CSS 默认   | canvas width/height: 100%，transform: none（无 cqi 时铺满壳，不再按内容撑高）              |
| CSS 现代机 | @supports (width: 1cqi) and (height: 1cqh) 内仍用原来的 375 + scale                        |
| 视口高度   | --app-viewport-height：首屏用 visualViewport.height（回退 innerHeight），跟地址栏/键盘更新 |
| 内容避让   | tabbed：`padding-bottom: tab + safe-bottom`；Tab 自身也吃 `--safe-bottom`                  |

### 原理

```
失效前：canvas 高度 = 内容高度 > 壳高度 → Tab 在壳底之下 → 被裁且不可滚
修复后：canvas 高度 = 壳高度 → Tab 的 bottom:0 落在壳底可见处
```

现代机仍走 scale，布局坐标还是 375；旧机走 100% 铺满，优先保证 Tab 在视口内。

## 右侧白条

### 原因

- 常见触发：只支持一半容器单位、或 @supports 进了 375 分支但 scale(calc(100cqi/375px)) 没真正铺满。

### 方法

1. 收紧 @supports：(width: 1cqi) and (height: 1cqh)，减少半残支持误进 375。
2. JS 兜底 useAppShellCanvasScale（不按 UA）：
   - 量：壳宽 - 画布 getBoundingClientRect().width
   - 差值 > 2px → 判定 scale 失效
   - 写入与 CSS 等价的 inline：

```
`scale = 壳宽 / 375`
`width = 375px`
`height = 壳高 / scale` ← 放大后视觉高度 = 壳高（保 Tab）
`transform = scale(scale)`
`transform-origin: top left`
```

一旦启用，本页会话内持续跟 resize；已铺满的机型不写 inline

### 原理

getBoundingClientRect() 含 transform 后的视觉宽度。

CSS scale 正常时视觉宽 ≈ 壳宽，JS 不介入。

失效时视觉宽 ≈ 375，JS 补上同一套「375 坐标 + 按壳宽放大」，白条消失，高度仍贴壳。
