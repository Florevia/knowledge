# Meta Pixel 与 PSI 推广归因

## 概述

投放进站场景里常同时出现 **Pixel（Meta Pixel）** 与 **PSI**：前者是 Meta 侧的网站行为追踪工具，后者是业务系统内部的推广链接编号。二者常一起出现在落地 URL 中，但职责不同，不能互相替代。

## 要点

- **Meta Pixel（原 Facebook 像素）**：网站上的追踪代码，记录行为并上报给 Meta，用于广告归因、转化统计与投放优化
- **PSI**：系统内部「推广链接唯一编号」，用于区分链接并关联广告访问与后续转化报表；不是通用广告行业术语
- URL 里的 `fbpid=...` 大概率是 Pixel ID，但**仅把 ID 放进链接不会自动追踪**，还需加载 Pixel 脚本或走 Conversions API（CAPI）
- 简单对照：**PSI 管「这条推广链接是谁」；Pixel 管「把网站行为交给 Meta 衡量」**

## 详细内容

### 1. Meta Pixel 是什么

Facebook 像素现在叫 **Meta Pixel**，是一段安装在网站上的追踪代码，主要做两件事：

1. **记录用户行为**  
   例如：浏览页面、注册账号、加入购物车、充值或购买
2. **把行为上报给 Meta**  
   - 判断某次注册或购买来自哪条 Facebook / Instagram 广告  
   - 统计广告转化效果  
   - 帮助 Meta 优化投放、寻找相似用户（Lookalike 等）

典型链路（如广告进小说站并充值）：

```text
点击广告 → 进入网站 → 注册 → 充值
```

Pixel 把注册、充值等事件上报后，广告后台才能把转化记到对应广告上。

### 2. URL 中的 `fbpid`

例如：

```text
fbpid=790455510043753
```

大概率表示 **Pixel ID**，用来指定事件归属/上报到哪个 Meta Pixel。

注意：

- 只把 Pixel ID 写进 URL **不会自动完成追踪**
- 网站还需：
  - 加载 Meta Pixel 脚本（浏览器端上报），和/或
  - 由服务端通过 **Meta Conversions API（CAPI）** 上报事件

前端 Pixel 与服务端 CAPI 常配合使用，并做事件去重（例如统一用订单号作为 event id）。

### 3. PSI 是什么

`PSI` **不是**通用广告行业标准术语，更像业务系统内部定义的「**推广链接唯一编号**」。

例如：

```text
psi_id = promotion2062456686144126977
```

用途通常是区分每条推广链接，并关联：

- 哪个广告/哪条链接带来的访问
- 后续注册、充值等转化
- 后台推广报表

**具体英文全称需向方案提出方确认**，不能仅凭 `psi_id` / `psi` 字段名臆测。

### 4. PSI 与 Pixel 对照

| | PSI | Pixel（Meta Pixel） |
|--|-----|---------------------|
| 归属 | 你们自己的业务系统 | Meta 广告生态 |
| 本质 | 推广链接唯一编号 | 网站统计/转化追踪代码（及对应 Pixel ID） |
| 回答的问题 | 这条推广链接是谁 / 归哪条推广 | 用户在站上做了什么，能否归因到 Meta 广告 |
| 典型标识 | `psi` / `psi_id` | `fbpid`（Pixel ID）、Pixel 脚本、CAPI |
| 能否互相替代 | 否：PSI 不能代替向 Meta 上报 | 否：Pixel 不替代你们内部推广报表主键 |

一句话：

- **PSI**：自己用来追踪「这条推广链接是谁」
- **Pixel**：Meta 用来收集网站行为、衡量广告效果

### 5. 与其他常见归因参数的关系（补充）

投放进站时，URL / 落地上下文里还可能同时出现：

| 参数 | 含义（常见） |
|------|----------------|
| `psi` / `psi_id` | 内部推广链接编号 |
| `fbpid` | Meta Pixel ID |
| `fbclid` | Facebook Click ID，广告点击带入，用于点击级归因 |
| `campaign_id` / `adset_id` / `ad_id` | Meta 广告层级 ID |
| `bookid` 等 | 业务落地内容 ID（如书） |

支付建单、注册落库时，通常需要把上述归因字段一并持久化到用户/订单上，才能把「广告 → 进站 → 注册 → 付费」串成完整报表，并与 Pixel / CAPI 事件对齐。

### 6. 落地实践注意

- **有 `fbpid` ≠ 已追踪**：必须确认 Pixel 初始化或 CAPI 实际上报成功
- **PSI 与 Pixel 都要存**：PSI 服务内部报表；Pixel/CAPI 服务 Meta 投放优化
- **私有页与合规**：登录态、钱包等页的追踪策略需与隐私政策、noindex 等策略一并考虑
- **事件命名与去重**：注册、InitiateCheckout、Purchase 等标准事件名尽量对齐 Meta 约定；浏览器与 CAPI 双报时用统一 event id 去重
